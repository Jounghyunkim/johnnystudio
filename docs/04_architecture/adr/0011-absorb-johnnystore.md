# ADR-0011: JohnnyStore 를 JohnnyStudio 로 흡수하고, 파일을 올리는 사람은 운영자뿐이다

- **상태**: 일부 대체됨 (→ ADR-0012: 결정 2·6, 결정 4 의 신고·관리자·이용약관)
- **날짜**: 2026-11-22 (한 세션에서 Q1·Q3·Q4·Q8, 이어서 Q2·Q5·Q6·Q7·Q9 답을 받아 커밋 전에 함께 확정했다)
- **관련**: [JohnnyStore 통합 검토](../../02_planning/features/johnnystore-integration.md), [ideation §8](../../ideation.md) (하지 않을 것), [ADR-0005](0005-file-based-content.md) (파일 콘텐츠),
  [ADR-0007](0007-magic-link-auth-api.md) · [ADR-0008](0008-password-login.md) (회원 API, 인증 단일 권위), [ADR-0009](0009-local-portfolio-manager.md) (작품 관리 도구)

## 맥락

- 사용자 요청: "JohnnyStudio 에 `../johnnystore` 를 합쳐서 하나의 서비스로 만든다."
- JohnnyStore 는 "누구나 Windows 프로그램을 올리고 링크로 공유하는 오픈 앱 스토어"다 (FastAPI + React SPA, SQLite).
  - 인증: 이메일 인증 없는 즉시 가입, JWT 를 localStorage 에 둔다, bcrypt, GitHub·Google OAuth
  - 기능: 설치 파일 분석(PE 헤더·아이콘), VirusTotal·ClamAV 검사, 공개 범위(PUBLIC·UNLISTED·PROTECTED), 공유 링크·QR·배지·동적 OG, 신고·차단
- 2026-11-22 스토어 DB(읽기 전용 조회): 회원 1명(운영자), 앱 9개(모두 운영자 것, 모두 PUBLIC), 신고 0건, 저장 파일 180MB.
  JohnnyStudio 의 데스크톱 앱은 내용 없는 초안 2개뿐이다.
- "누구나 업로드"는 ideation §8 의 하지 않을 것 "의뢰인이 아닌 사람의 파일 업로드는 받지 않는다"와 부딪힌다.
- 스토어는 작업 폴더에서 `0.0.0.0:4000` 으로 떠 있었고, 공인 주소의 4000 포트로도 응답했다 (2026-11-22 확인). `.env` 가 없어서 가입 정책이 기본값 `open` 이었다.
- 스토어 주소(`/s/`, `/d/`, `/@johnny/…`)는 밖에 공유한 적이 없다 (사용자 확인).

## 검토한 선택지

통합 방식

| 선택지 | 장점 | 단점 |
|---|---|---|
| 나란히 두기 (`store.<도메인>` 에 그대로) | 일이 가장 적다 | 인증·디자인·배포·검사가 두 벌. "하나의 서비스"가 아니다. 스토어의 낮은 보안 수준(localStorage JWT, 이메일 인증 없음, CSP 없음)이 남는다 |
| **흡수 (JohnnyStudio 기준)** | 인증·디자인·배포가 하나. 파일 원본·해시 CSP 원칙 유지 | 스토어 화면을 다시 만든다 |
| 스토어를 기준으로 | 동적 기능이 이미 있다 | ADR-0004·0007·0008 을 뒤집는다. 정적 HTML·CSP·인증 수준이 내려간다 |

누가 올리나 (검토 문서 §2-3)

| 선택지 | 장점 | 단점 |
|---|---|---|
| **A. 운영자 전용** | 철학과 맞다. 운영 부담·법적 위험이 낮다 | 스토어의 오픈 플랫폼 기능을 버린다 |
| B. A + 테스터·의뢰인 비공개 공유 | 협업 원칙 강화, Client Room 토대 | 동적 저장소·만료·접근 기록이 필요하다 |
| C. 누구나 업로드 | 스토어 원래 목표 | 비목표 변경. 신고·검사·통지가 상시 업무가 된다. 남이 올린 악성 파일로 포털 도메인 평판이 떨어질 수 있다 |

## 결정

1. **JohnnyStore 를 별도 서비스로 운영하지 않는다.** JohnnyStudio 가 기준이다. 인증(회원 API), 디자인(토큰), 배포(Tunnel → nginx 127.0.0.1:8081), 검사(`check.sh`)를 그대로 쓴다.
2. **파일을 올리는 사람은 운영자뿐이다** (사용자 결정, 선택지 A).
   - 다른 사람의 가입·업로드, 퍼블리셔 프로필(`/@username`), 인기 차트, 신고·차단 관리는 만들지 않는다
   - ideation §8 의 "의뢰인이 아닌 사람의 파일 업로드는 받지 않는다"를 그대로 둔다
3. **운영자 앱의 원본은 `content/` 파일이다** (ADR-0005). 스토어의 앱 9개를 `desktop-app` 작품으로 옮긴다.
   - 설치 파일은 `/opt/johnnystudio/files/<slug>/`, 아이콘은 `web/public/media/<slug>/`
   - 설치 파일은 지금처럼 홈 서버(`/files/`)에서만 낸다. 큰 파일(CMG Monitor 118MB)도 같다 (사용자 결정. ideation §9-6 의 답)
   - WLT·CMG Monitor 는 기존 초안 `ssh-terminal`·`hardware-monitor` 와 같은 앱이다 (사용자 확인). 스토어 slug(`wlt`·`cmg-monitor`)로 만들고 초안 2개를 대신한다
   - 상태·날짜는 스토어와 같게 한다 (사용자 결정): 운영 중, 2026-11-16 (스토어에 공개한 날)
4. **가져오는 것**: 설치 파일 분석(`pe_extractor`), 바이러스 검사(`scanner`, 로컬 ClamAV 우선), 공유 키트(바로 받기 링크·배지·QR, 빌드 때 정적으로).
   **가져오지 않는 것**: 가입·로그인·JWT·bcrypt·OAuth 코드, React 화면과 CSS, 봇 감지 동적 OG, 프로세스 메모리 요청 제한, 신고·관리자·이용약관.
   설치 파일 분석·검사를 관리 도구에 붙이는 방식은 구현할 때 따로 ADR 로 남긴다
5. **비공개 공유(선택지 B)는 이 통합에 넣지 않는다.** 필요하면 Phase 3 Client Room 에서 설계하고, 스토어의 링크 전용·접근 코드·다운로드 토큰을 참고한다.
6. **운영 서버에 웹으로 파일을 올리는 길은 만들지 않는다.** 운영자는 서버(M8) 안의 관리 도구(ADR-0009)로 올린다.
7. **스토어 서비스는 끈다** (2026-11-22). 먼저 가입을 닫았고(`JS_REGISTRATION=closed`), 저장소를 지우기로 해서 같은 날 프로세스와 `screen` 세션을 끝냈다.
   - 옛 주소는 공유한 적이 없으므로 리다이렉트를 두지 않는다
   - 공유기의 4000 포트 전달은 사용자가 지운다
8. **johnnystore 저장소는 지운다** (사용자 결정).
   - 지우기 전에 전체(소스·git 이력·미커밋 작업·데이터)를 `~/workspace/backup/johnnystore/johnnystore-20261122.tar.gz` 로 보관하고 확인했다 (설치 파일 9개 SHA-256 일치, 아이콘 9개)
   - 이 보관본이 이관(S1)과 코드 이식(S2)의 원본이다. 커밋 메시지에는 출처를 `johnnystore 6dc01fe (보관본)` 처럼 쓴다
   - 이식이 끝나면 보관본도 지운다 (운영자 이메일·비밀번호 해시·서명 키가 들어 있다)
   - GitHub 저장소 `Jounghyunkim/johnnystore` 는 사용자가 지운다 (gh 토큰에 `delete_repo` 권한이 없다)
   - 스토어 이력을 `git subtree` 로 들이지 않는다
9. **"JohnnyStore" 이름은 남기지 않는다** (사용자 결정). 데스크톱 앱은 Library 안에서 보여 준다.

## 결과

- **좋아지는 점**
  - 실제 Windows 앱 9개가 Library 에 들어가 Phase 1 의 콘텐츠 공백 대부분이 메워진다
  - 인증·디자인·배포·검사가 하나로 남는다. 운영 공격면이 늘지 않는다
  - 스토어의 신뢰 표시(아키텍처·서명 블록·검사 결과)와 공유 키트가 Trust by Design·무마찰 접근 원칙을 강화한다
- **감수할 점**
  - 스토어의 오픈 플랫폼 기능(누구나 업로드, 퍼블리셔 페이지, 신고 처리)과 React 화면은 버린다
  - 운영 서버에 웹으로 올릴 수 없다. 앱을 올리려면 M8 에서 관리 도구를 띄워야 한다
  - 스토어를 먼저 껐기 때문에, JohnnyStudio 를 공개(도메인·Tunnel)하기 전까지 앱 9개를 밖에서 받을 곳이 없다 (주소를 공유한 적이 없어서 영향은 작다)

## 재검토 조건

- 다른 사람의 앱이나 파일을 받아야 할 일이 생길 때: 새 ADR 로 비목표를 바꾸고, 별도 다운로드 도메인·이용약관·신고 절차를 먼저 정한다 (검토 문서 S5)
- 테스터·의뢰인에게 공개하지 않은 빌드를 Phase 3 전에 보내야 할 때 (검토 문서 S4)
- 운영 서버 밖(다른 기기)에서 앱을 올려야 할 때
