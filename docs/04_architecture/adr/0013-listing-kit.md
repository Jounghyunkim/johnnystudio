# ADR-0013: Store·Showroom 소개 자료: 공통 항목(Microsoft Store 와 같은 한도) + AI 키트 + 브라우저에서 읽는 md·zip

- **상태**: 제안됨
- **날짜**: 2026-11-25
- **관련**: [ADR-0012](0012-member-store.md) (회원 Store·Showroom, 결정 9 의 '고치면 바로 반영'), [소개 자료 기능 명세](../../02_planning/features/listing.md),
  [Store](../../02_planning/features/store.md) · [Showroom](../../02_planning/features/showroom.md) 명세, [ADR-0004](0004-nextjs-static-export.md) (정적 내보내기)

## 맥락

- 사용자 요청 (2026-11-25): "Library(Store 및 Showroom)에 게시물을 등록하는 과정에 대해서 좀 쉽고 AI Agent(Claude 또는 Gemini)를 통해 업로드하기 쉽게 게시물을 꾸미는데 필요한 항목(예를들어 숏컷이미지, 아이콘, 설명, 카테고리, 연관검색어, 기능 등등..)들을 나열 검토하고 사람이 직접 입력 또는 관련 MD파일(AI를 통해 특정 양식으로 생성한 내용 파일)을 입력하면 파싱해서 자동으로 기입이 되도록 그리고 이미지도 AI를 통해 특정 양식으로 생성한 이미지들 및 Web service의 경우 자동으로 스크린 캡쳐 되도록 그래서 리뷰 블로그 또는 블로그 수준의 멋진 소개 자료가 완성될 수 있도록 AI Coding Tool에 전달할 프롬프트 복사 기능 추가하고 게시물 등록 시 그 프롬프트로 생성한 zip파일(images, description, 등 파일 구조 포함) 또는 md파일(여러 입력폼의 설명 파싱용, 이미지는 따로 업로드)을 업로드하면 간편하게 업로드 준비할 수 있는 기능을 추가해 줘."
- 작업 중 추가 요청 (같은 날): "사용하는 항목들은 MS Store 앱 등록할 때 등록하는 항목들을 포함하여 공통으로 사용할 수 있도록 해주세요."
- 지금 Store 앱은 이름·한 줄 소개·설명(5000자, 글자 그대로)·분류·아이콘, Showroom 서비스는 여기에 주소·화면 그림 한 장뿐이다. 리뷰 글처럼 보여 줄 칸이 없다.
- 제약
  - 기존 테이블에 열을 더하면 `create_all` 이 고치지 않는다 (개발 DB 를 지워야 한다, 2026-11-24 작업 로그 메모)
  - 회원이 쓴 글은 HTML 로 넣지 않는다. 회원 그림은 API 프로세스에서 풀지 않는다 (AGENTS.md §5)
  - nginx 의 `/api/` 본문 한도가 16k 라서 한글 5000자 설명(약 15KB)도 이미 경계에 있다. `/api/` 요청 제한(분당 30번)은 그림 여러 장을 읽는 상세 화면에 맞지 않는다
  - 이 서버는 집 안 네트워크에 있다 (같은 기기에 Arkurator·My Claude Inspector, 공유기 안쪽 기기들)

## 검토한 선택지

| 문제 | 선택지 | 장점 | 단점 |
|---|---|---|---|
| 웹 서비스 화면 캡처 | **A. AI 도구가 회원 PC 에서 Playwright 로 캡처 (프롬프트로 지시)** | 서버가 남의 주소를 열지 않는다. 로그인한 화면·개발 서버도 찍는다 | 회원이 AI 도구·Playwright 를 써야 한다 |
| | B. 서버가 헤드리스 브라우저로 회원 주소를 찍기 | 회원이 할 일이 없다 | 홈 서버가 회원이 준 주소를 연다 (SSRF: 리다이렉트·DNS 바꿔치기로 192.168.x·127.0.0.1 서비스에 닿을 수 있다). Chromium 설치·메모리·샌드박스 |
| md·zip 읽기 | **A. 브라우저에서 읽어 양식을 채우고, 사람이 확인한 뒤 낸다** | 서버는 zip 을 받지 않는다 (압축 폭탄·경로 조작을 서버에서 다루지 않는다). 확인 단계가 생긴다 | 클라이언트 코드가 늘어난다 (zip 읽기를 직접 짬) |
| | B. 서버가 zip 을 받아 풀고 바로 등록 | 한 번에 끝난다 | 서버가 남의 zip 을 푼다. 확인 없이 들어간다 |
| zip 라이브러리 | **A. DecompressionStream("deflate-raw") 로 직접 (의존성 없음)** | 새 의존성 없음, 50여 줄 | 저장·Deflate 만, zip64 없음 |
| | B. fflate 등 | 형식을 더 받는다 | 새 의존성 |
| 저장 | **A. 소개 자료를 JSON 으로 새 테이블(`store_app_pages`·`showroom_service_pages`)에** | 기존 테이블을 안 건드린다. 항목을 더하기 쉽다 | 칸마다 DB 제약이 없다 (서버 코드가 검사) |
| | B. 칸마다 열·테이블 | DB 가 모양을 지킨다 | 기존 테이블 변경·마이그레이션 |
| 설명 표시 | **A. Markdown 일부를 marked 의 lexer 토큰으로 받아 React 요소로 그린다** | 이미 있는 의존성. HTML 을 넣지 않는다 | 허용한 모양만 보인다 |
| | B. 글자 그대로 (지금) | 가장 단순 | 블로그 수준이 안 된다 |
| 항목·한도 | **A. Microsoft Store(Partner Center) 등록 항목과 같은 한도로 맞추고, 칸별 복사 화면을 둔다** | 한 번 만든 자료를 두 곳에 쓴다 (사용자 요청) | 사이트에는 약간 빡빡한 한도 (기능 설명 150자 등) |

## 결정

1. **공통 항목** (Store·Showroom 이 같은 모양, `api/app/listing.py` · `web/src/lib/listing.ts`):
   기존 칸(이름·한 줄 소개·설명·분류, Showroom 주소, Store 버전·바뀐 점)에 더해 연관 검색어, 추천 대상, 주요 기능(그림 1장 연결), 사용 방법, 필요한 환경(최소·권장), 가격,
   자주 묻는 질문, 관련 링크, 그림 모음(첫 장이 대표), 개발자, 저작권·상표 정보, 라이선스, 웹 사이트, 지원 연락처, 개인정보처리방침 주소, Microsoft Store 주소·분류.
2. **한도는 Microsoft Store 등록 항목에 맞춘다** (learn.microsoft.com 의 Windows 앱 제출 문서, 2026-11-25 확인): 설명 10,000자 · 바뀐 점 1,500자 · 제품 기능 20개(이름 40자 + 설명 150자 → "이름 — 설명" 200자 안) ·
   검색어 7개 × 30자(단어 합계 21개) · 그림 10장·설명 200자 · 최소·권장 환경 각 11개 × 200자 · 저작권 200자. 바뀐 점은 2000 → 1500자로 줄인다.
3. **Microsoft Store 제출용 항목**: 편집 화면에서 Partner Center 칸 이름(한국어·영어)대로 값·글자 수·빈 필수 칸을 보여 주고 칸마다·전체를 복사한다. 설명은 Markdown 표시를 걷어 낸 일반 글로.
   연령 등급·가격 정책·출시 국가는 다루지 않는다 (Partner Center 에서 정한다).
4. **소개 자료 파일 양식 `johnnystudio-listing/1`**: `listing.md`(YAML 머리말 + 정해진 `##` 절, 절 이름은 한국어·영어 별칭을 받는다) + `images/`(사이트와 Microsoft Store 공용 PNG) + `ms/`(Microsoft Store 전용, 사이트는 읽지 않음)를 zip 으로.
   md 만 올리면 글만 채우고, 같은 이름의 그림 파일을 고르면 설명·기능 자리에 맞춰 넣는다.
5. **읽기는 브라우저에서만** 한다. 서버는 정리된 값(JSON)과 그림 파일(하나씩)만 받는다. zip 읽기는 직접 짠다(저장·Deflate, 항목 300개, 꺼내는 항목 12MB, 파일 200MB).
6. **AI 키트**: 프롬프트 복사·양식(listing.md) 내려받기·안내 페이지(`/store/guide/`). 프롬프트는 지어내지 않기, 실제 화면만, 개인정보 가리기, 바깥 서비스에 올리지 않기를 먼저 요구하고,
   웹 서비스 화면은 AI 도구가 **회원 PC 에서 Playwright 로 1920×1080 캡처**하게 한다. 서버는 회원 주소를 열지 않는다 (선택지 B 를 하지 않는다).
7. **그림**: 한 장 5MB 원본 → 자식 프로세스(`run_screenshot_isolated`)가 긴 변 1600px WebP 로 다시 그려 `<store_dir>/gallery/<store|showroom>/<코드>/<무작위 ID>.webp` 에 둔다.
   그림 ID 가 바뀌지 않으므로 `Cache-Control: private, max-age=604800` 을 준다 (API 의 기본 `no-store` 를 이 응답만 덮어쓴다). 그림 모음에서 뺀 그림은 파일도 지운다.
8. **설명 표시**: marked 의 lexer 토큰 중 문단·제목·목록·인용·코드·표·굵게·기울임·취소선·링크만 그린다. 링크는 https 만, 새 탭·UGC rel·호스트를 함께 보인다. HTML·그림 토큰은 글자로.
9. **권한·검토**는 ADR-0012 그대로: 올린(소개한) 사람과 운영자가 고친다 (Showroom 의 운영자 고치기는 2026-11-26 에 더했다, ADR-0012 결정 12). 고치면 바로 반영되고(신고·숨김으로 사후 대응) Showroom 서비스 주소만 다시 검토한다.
   반려된 Showroom 서비스는 소개 자료를 고쳐도 다시 검토 대기로 간다. 관련 링크·지원 연락처는 고치면 바로 바뀐다 (호스트를 보여 주고 UGC rel).
10. **nginx**: `/api/store/apps`·`/api/showroom/services` 를 따로 받아 본문 128k(한글 설명 10,000자·소개 자료), 그 안의 아이콘·그림 GET 은 요청 제한 `johnnystudio_media`(분당 300, 몰아서 60).
11. 목록 검색은 이름·소개에 더해 연관 검색어도 본다. Showroom 의 예전 화면 그림 한 장은 그림 모음이 없을 때만 보이고, 새로 올리는 곳은 그림 모음으로 바꾼다.

## 결과

- **좋아지는 점**: AI 도구로 리뷰 글 수준의 소개를 몇 분 안에 준비한다. 같은 자료로 Microsoft Store 에도 올린다. 서버는 zip·남의 주소를 다루지 않는다.
  기존 테이블을 바꾸지 않는다. 한글 긴 설명이 운영 nginx 에서 413 으로 막히던 문제(기존 5000자에도 있던 경계)도 풀린다.
- **감수할 점**
  - 웹 화면 자동 캡처는 회원이 AI 도구·Playwright 를 쓸 때만 된다
  - Microsoft Store 한도가 바뀌면 두 곳(`listing.py`·`listing.ts`)과 제출용 항목 문구를 함께 고쳐야 한다
  - AI 가 쓴 글이 사실과 다를 수 있다. 프롬프트·안내로 막고, 운영자 검토·신고로 사후 대응한다
  - 회원이 공개하는 지원 연락처(이메일)가 화면에 보인다 (개인정보처리방침에 적었다)
  - 이용약관은 고치지 않았다 (회원이 올리는 글·그림의 범위 안이라고 봤다) `[확인 필요: 사용자]`

## 재검토 조건

- 회원이 AI 도구 없이도 화면 캡처를 원하는 일이 많아지면: 격리된 캡처 전용 환경(바깥만 나가는 망, 별도 기기·컨테이너)을 먼저 마련한 뒤 서버 캡처를 다시 검토한다
- Microsoft Store 의 칸·한도가 바뀌면 (Partner Center 문서)
- 소개 자료에 영상(트레일러)·여러 언어를 넣고 싶어지면
- Library(운영자 작품) 관리 도구에서도 같은 양식을 불러오고 싶어지면 (`content/assets` 스키마와 맞추는 일)
