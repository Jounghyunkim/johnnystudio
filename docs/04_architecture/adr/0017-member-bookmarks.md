# ADR-0017: 회원의 즐겨찾기는 계정(DB)에 두고, 비회원은 지금처럼 브라우저에 둔다

- **상태**: 제안됨
- **날짜**: 2026-11-27
- **관련**: [ideation §3-3](../../ideation.md) (My Studio Phase 1 → 2: 로그인하면 동기화), [ADR-0007](0007-magic-link-auth-api.md) (인증은 FastAPI 하나),
  [ADR-0008](0008-password-login.md), [ADR-0015](0015-library-as-official-view.md) (즐겨찾기 값은 하나)

## 맥락

- 사용자 요청 (2026-11-27): "즐겨찾기 및 My Studio가 사용자별로 DB에 저장되는 구조인지 브라우저에 저장되는 구조인지 확인하고
  사용자별 즐겨찾기가 관리되고 다른 브라우저에서도 즐겨찾기를 불러올 수 있도록 수정해 주세요."
- 확인 결과: 즐겨찾기(My Studio)는 **브라우저 localStorage(`johnnystudio:bookmarks:v1`)에만** 있었다. DB 에는 즐겨찾기 테이블이 없었고,
  로그인해도 다른 브라우저·기기에서는 보이지 않았다. ideation §3-3 은 이것을 Phase 1 로 두고 "로그인하면 서버에 동기화"를 Phase 2 로 미뤄 두었다.
- 회원 가입·로그인(세션 쿠키)은 이미 있다 (ADR-0007·0008). 공개 기능은 로그인 없이 쓴다는 원칙(PHILOSOPHY)은 지킨다.

## 결정

1. **로그인했으면 즐겨찾기는 계정에 저장한다.** 테이블 `bookmarks(user_id, item, created_at)`, `(user_id, item)` 은 겹치지 않는다. 넣은 순서(id)대로 보인다.
   - API (`app/bookmarks.py`, 로그인 필요): `GET /api/account/bookmarks`, `POST /api/account/bookmarks {items}` (없는 것만 뒤에 더한다),
     `DELETE /api/account/bookmarks/{item}`. 셋 다 바뀐 뒤의 전체 목록을 돌려준다. 쓰기는 다른 API 와 같이 Origin 검사를 거친다
   - 값의 형식은 지금과 같다: Library 작품 slug, Store 앱 `store:<코드>` (ADR-0015). 서버는 형식만 보고, 공개 여부는 My Studio 가 보일 때 거른다
   - 한 사람 500개까지. 탈퇴하면 함께 지운다
2. **로그인하지 않았으면 지금처럼 이 브라우저에만 둔다.** 서버는 비회원의 즐겨찾기를 모른다.
3. **로그인하면 이 브라우저의 목록을 계정에 한 번 더하고(겹치는 것은 하나) 브라우저에서는 지운다.** 로그아웃하면 이 브라우저에는 계정 목록이 남지 않는다
   (같이 쓰는 컴퓨터). 옮기기에 실패하면 브라우저 목록을 지우지 않고 다음에 다시 더한다.
4. **화면은 누르는 즉시 바뀌고(낙관적), 요청은 하나씩 차례로 보낸다.** 마지막 요청의 답(서버의 전체 목록)으로 화면을 맞춘다. 실패하면 서버가 마지막으로 알려 준 목록으로
   되돌리고 다시 불러온다 (My Studio 에 '다시 불러오기'). 세션이 끝났으면(401) 로그인 상태를 다시 묻는다. 다른 탭·기기에서 바꾼 것은 탭으로 돌아올 때(30초가 지났으면) 다시 불러온다.
   회원 서버에 닿지 않으면 브라우저 목록을 쓰고, 다음에 로그인이 확인되면 계정에 더한다.
5. 정적 HTML 에는 즐겨찾기가 들어가지 않는다 (지금과 같다). 로그인 상태는 이미 헤더가 묻는 `GET /api/auth/me` 를 함께 쓴다.

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| **A. 회원은 DB, 비회원은 브라우저 (채택)** | 로그인 없이도 쓰는 원칙을 지킨다. 회원은 어느 브라우저에서나 같은 목록. ideation 계획과 같다 | 저장 위치가 둘이라 로그인할 때 옮기는 규칙이 필요하다 |
| B. 모두 DB (로그인해야 즐겨찾기) | 원본이 하나 | 공개 기능은 로그인 없이 쓴다는 원칙과 다르다. 지금 비회원이 넣은 목록을 잃는다 |
| C. 로그인해도 브라우저 목록을 함께 두고 양쪽을 합친다 | 오프라인에서도 보인다 | 지운 것이 다시 살아나는 문제(어느 쪽이 맞는가)가 생긴다. 같이 쓰는 컴퓨터에 남는다 |

## 결과

- **좋아지는 점**: 회원은 다른 브라우저·기기에서 로그인해도 같은 My Studio 를 본다. 로그인 전에 넣은 즐겨찾기도 잃지 않는다.
- **나빠지는 점·주의**
  - 새 개인정보(회원의 즐겨찾기 목록)를 저장한다 → 개인정보처리방침에 적었다 (탈퇴할 때까지, 탈퇴하면 바로 지움)
  - 같이 쓰는 컴퓨터에서 남이 로그인하지 않고 넣은 즐겨찾기가, 그 브라우저에서 내가 로그인하면 내 계정에 더해질 수 있다 (흔한 장바구니 합치기와 같다). 계정에서 빼면 된다
  - 새 테이블은 API 가 시작할 때 만든다 (`create_all`, 이미 있는 테이블은 바꾸지 않는다). 운영 DB 에 따로 할 일은 없다
- **재검토 조건**: 즐겨찾기한 앱의 새 버전 알림(ideation §3-3)을 만들 때, 또는 Showroom 서비스 즐겨찾기를 따로 둘 때 값의 형식을 다시 본다
