# ADR-0001: 포털은 빌드 없는 정적 HTML/CSS/JS 로 시작한다

- **상태**: 대체됨 (→ [ADR-0004](0004-nextjs-static-export.md)). 재검토 조건("로그인처럼 서버 처리가 필요한 기능")에 해당하는 기획(ideation v2)이 나왔다
- **날짜**: 2026-11-05
- **관련**: [ADR-0002](0002-deploy-home-server-nginx.md)

## 맥락

- JohnnyStudio 포털(허브)을 새로 만든다. 철학과 콘텐츠가 아직 정해지지 않아서 요구사항이 열려 있다.
- 첫 단계 포털이 할 일은 스튜디오 소개와 프로젝트 연결이다. 로그인이나 DB 같은 서버 기능은 필요 없다.
- 개발·운영 서버(M8)에는 Python 3 과 nginx 가 있고 Node.js 는 없다.
- 형제 프로젝트 Arkurator 는 PHP + Tailwind 구성이다 (Tailwind 빌드가 필요하다).

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| **정적 HTML/CSS/JS (빌드 없음)** | 도구를 설치하지 않고 바로 시작할 수 있다. 어디든 배포할 수 있다. AI 도구가 결과물을 그대로 읽고 고칠 수 있다 | 헤더·푸터를 페이지마다 복사해야 한다. 페이지가 늘면 관리 부담이 커진다 |
| PHP + Tailwind | Arkurator 와 같은 스택이다. include 와 다국어 처리가 쉽다 | M8 에 PHP-FPM 을 추가로 설치해야 한다. Tailwind 빌드에 Node 가 필요하다 |
| Astro (정적 사이트 생성기) | 컴포넌트와 마크다운 콘텐츠를 쓸 수 있어 페이지가 많아져도 관리가 쉽다 | Node 설치와 빌드 단계가 필요하다. 요구사항이 정해지기 전에는 과하다 |

## 결정

빌드 없는 정적 사이트로 시작한다. `src/` 가 그대로 웹 루트가 된다.

- 콘텐츠는 HTML 에 직접 쓴다. JS 로 렌더링하지 않는다 (검색엔진 색인, JS 를 끈 환경 대비).
- 외부 CDN 을 쓰지 않는다. 폰트와 스크립트도 `src/assets/` 에 둔다.
- CSS 는 디자인 토큰(CSS 변수) 기반으로 짠다. 나중에 어떤 스택으로 옮겨도 그대로 가져갈 수 있게 하기 위해서다.

## 결과

- **좋아지는 점**: 오늘 바로 개발할 수 있다. 배포는 파일 복사로 끝난다. 의존성 업데이트나 보안 패치 부담이 없다.
- **감수할 점**: 페이지 사이의 공통 부분(헤더·푸터)을 손으로 맞춰야 한다. 페이지가 적은 동안은 감수한다.

## 재검토 조건

하나라도 해당되면 SSG(Astro 등) 또는 서버 기능 도입을 검토하는 새 ADR 을 쓴다.

- 페이지가 5개를 넘어 헤더·푸터 복사에서 실수가 나기 시작할 때
- 블로그나 작업 노트처럼 마크다운으로 자주 쓰는 콘텐츠가 생길 때
- 한·영 페이지를 동시에 운영해야 할 때
- 문의 폼이나 로그인처럼 서버 처리가 필요한 기능이 생길 때
