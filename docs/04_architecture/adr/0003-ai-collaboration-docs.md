# ADR-0003: AI 협업 문서 체계 (AGENTS.md · docs · dev_history · ADR)

- **상태**: 채택됨
- **날짜**: 2026-11-05

## 맥락

- 이 프로젝트는 AI 도구로 개발한다. 도구는 하나가 아닐 수 있다.
- AI 세션은 이전 대화를 기억하지 못한다. 매번 맥락을 다시 설명하면 시간이 들고, 설명이 빠지면 같은 실수가 반복된다.
- "지금 상태", "바뀐 과정", "결정한 이유"가 한 문서에 섞이면 문서가 길어지고 낡은 내용이 남는다.

## 결정

| 위치 | 담는 것 | 쓰는 방식 |
|---|---|---|
| `AGENTS.md` | 모든 AI 도구의 공통 작업 규칙 | 단일 원본이다. `CLAUDE.md` 는 `@AGENTS.md` 로 불러오고 Claude 전용 내용만 덧붙인다 |
| `docs/ROADMAP.md` | 단계별 진행 상황 | 세션을 시작하면 가장 먼저 읽는다. 할 일을 끝내면 체크한다 |
| `docs/` | 현재 상태 (기획·설계) | 항상 최신으로 고쳐 쓴다 |
| `docs/04_architecture/adr/` | 결정과 그 이유 | 결정을 바꿀 때는 새 ADR 로 대체한다 (기존 ADR 은 고치지 않는다) |
| `dev_history/` | 세션별 작업 로그 | 이어서 쓰기만 한다 (쓴 내용은 고치지 않는다) |

`AGENTS.md` 라는 파일명은 여러 AI 코딩 도구가 공통으로 읽는 관례를 따른 것이다.

## 결과

- **좋아지는 점**: 새 세션이나 다른 도구도 `ROADMAP.md` → 최근 `dev_history` 순서로 읽으면 맥락을 이어받을 수 있다.
  결정의 이유가 남아서 같은 논의를 반복하지 않는다.
- **감수할 점**: 세션을 끝낼 때마다 기록하는 습관이 필요하다. Claude Code 에서는 `/worklog` 명령으로 부담을 줄인다.

## 재검토 조건

- 기록이 실제로 읽히지 않거나, 문서가 코드와 자주 어긋나기 시작할 때
