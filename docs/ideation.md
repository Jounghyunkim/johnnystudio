## 0. 한눈에 보기

> **JohnnyStudio 는 정현 님이 만든 모든 것(소프트웨어·영상·사진·글·하드웨어)을 한곳에 모아 보여 주고,
> 바로 써 보게 하고, 함께 일하는 셀프 호스팅 스튜디오다.** (한 문장 정의 제안)

하나의 사이트를 **방문 목적에 따라 네 구역**으로 나눈다. 원안의 컨셉들은 각자 다른 사람을 위한 것이다.
구역을 나누면 권한, 보안 수준, 구현 순서가 자연스럽게 정해진다.

| 구역 | 누가 | 무엇을 | 접근 | 단계 |
|---|---|---|---|---|
| **Showcase**: Library · Life Log · About | 모든 방문자 | 작품 둘러보기, 실행·다운로드, 삶의 기록 | 공개 | Phase 1 |
| **Work with me** | 잠재 의뢰인 | 제공 서비스, 진행 방식, 의뢰 문의 | 공개 | Phase 1 |
| **My Studio** | 재방문자 | 즐겨찾기 모아 보기 | 로그인 없이(브라우저 저장) → 로그인하면 동기화 | Phase 1 → 2 |
| **Client Room** | 초대받은 의뢰인 | 결과물 확인·다운로드, 피드백 스레드 | 초대 + 로그인 | Phase 3 |
| (운영) | 정현 님 | 콘텐츠·의뢰 관리 | 운영자 | Phase 2 → 3 |

## 1. 개발 철학 (Development Philosophy)

원안의 네 가지 원칙을 유지하고, 원칙마다 **실천 기준**을 붙였다. 다섯 번째 원칙(신뢰)은 새로 추가한 것이다.
실천 기준이 있어야 기능 결정을 할 때 원칙을 근거로 쓸 수 있다.

### 1-1. Digital Twin & Life Log (디지털 자아와 삶의 기록)

과거의 흔적(로봇, 영상, 블로그)부터 현재의 최신 프로젝트(AI 에이전트, Arkurator 등), 그리고 앞으로의 계획까지 모든 궤적을 담는 공간.

- **이렇게 한다**: 모든 결과물에 "언제, 왜 만들었나"(날짜·맥락·상태)를 함께 남긴다. 결과물과 마일스톤은 하나의 타임라인(Life Log)으로 이어진다.
- **이렇게 한다**: 완성작만이 아니라 개발 중이거나 보관된 프로젝트도 기록할 수 있다. 공개 여부는 항목마다 고른다.

### 1-2. Sovereignty & Self-Hosting (데이터 주권과 독립성)

미니 PC 홈랩으로 인프라의 주도권을 쥐고, 플랫폼 종속에서 벗어난 아지트를 만든다.

- **이렇게 한다**: 콘텐츠 원본은 저장소의 **파일**로 둔다. git 이 이력을 남기고, 언제든 다른 곳으로 옮길 수 있다.
  Arkurator 의 "파일이 곧 데이터베이스" 원칙을 이어받는다.
- **현실적인 타협**: YouTube·GitHub·블로그는 **배포 채널**로 쓴다. 목록과 맥락의 원본은 JohnnyStudio 가 가진다.
  Cloudflare 는 관문(DNS·Tunnel)으로만 쓰고, 빠질 수 있게 설계한다 (nginx 직접 공개로 되돌릴 수 있다).

### 1-3. User-Centric Accessibility (사용자 중심의 무마찰 접근과 개인화)

방대한 자료 속에서도 방문자가 원하는 자료에 바로 도달하게 하고, 즐겨찾기로 자기만의 뷰를 만든다.

- **이렇게 한다**: 공개 기능은 전부 **로그인 없이** 쓸 수 있다. 공개 자료를 받으려고 회원가입할 필요가 없다.
- **이렇게 한다**: 홈에서 원하는 작품까지 **두 번의 클릭** 안에 도달한다. 검색, 유형 필터, 태그를 제공한다.
- **이렇게 한다**: 즐겨찾기는 로그인 없이도 쓴다 (브라우저에 저장). 로그인은 "기기 간 동기화"가 필요할 때만 한다.
- **이렇게 한다**: 모바일, 키보드, 스크린리더로 모든 기능을 쓸 수 있다 (WCAG AA).

### 1-4. Seamless Collaboration (끊김 없는 비즈니스 협업)

프리랜서로서 만든 결과물을 안전하게 전달하고, GitHub 처럼 명확하게 의뢰인과 소통하는 폐쇄형·개방형 하이브리드 작업 환경.

- **이렇게 한다**: 의뢰 한 건의 요청 → 작업 → 검수 → 납품을 **한곳에 이력으로** 남긴다. GitHub 개념에 대응시킨다 (§3-4).
- **이렇게 한다**: 의뢰인에게 GitHub 계정이나 복잡한 가입을 요구하지 않는다. 이메일 초대 링크로 들어온다.

### 1-5. Trust by Design (신뢰가 기본) ※ 추가 제안

실행 파일을 배포하고 의뢰인의 비공개 자료를 다루는 사이트에서는 **신뢰가 곧 기능**이다.

- **이렇게 한다**: 다운로드 파일마다 버전, 크기, SHA-256 체크섬, 변경 내역을 공개한다.
- **이렇게 한다**: 외부 코드(웹 패키지)는 포털과 **다른 출처**에서 격리해 실행한다. 의뢰인 자료는 초대받은 사람만 보고, 링크는 만료된다.
- **이렇게 한다**: 방문자를 추적하지 않는다. 분석은 쿠키 없는 셀프 호스팅 방식으로 한다.

## 3. 상위 컨셉 (High-Level Concepts)

### 3-1. Unified Asset Library (다목적 에셋 라이브러리)

원칙은 **하나의 스키마, 유형별 뷰어**다. 모든 결과물은 같은 카드 형식으로 보이고, 유형에 맞는 행동 버튼과 상세 뷰어를 가진다.

| 유형 | 예 | 카드 행동 | 상세 화면 | 파일 위치 |
|---|---|---|---|---|
| `web-app` 웹 서비스 | Arkurator | 실행 ↗ | 소개·스크린샷·실행 | 외부 URL 또는 하위 도메인 |
| `desktop-app` 데스크톱 툴 | 하드웨어 모니터링, SSH 터미널 | 다운로드 | 버전·OS·크기·SHA-256·검증 방법·변경 내역 | `/files/` (nginx) |
| `web-package` 단독 웹사이트 | zip 패키지 | 체험 ▶ | 격리된 iframe 체험 + zip 다운로드 | 별도 출처 (샌드박스 도메인) |
| `video` 영상 | YouTube | 재생 | 썸네일 → 클릭하면 재생 (youtube-nocookie) | YouTube |
| `gallery` 사진 | 사진 앨범 | 보기 | 사진 그리드 + 확대 보기 | `/files/` 또는 저장소 |
| `article` 글 | 블로그 글 | 읽기 ↗ | 요약 + 원문 링크 | 외부 블로그 |
| `hardware` 하드웨어 | 로봇·전자 작품 | 보기 | 사진·영상·설명 | 저장소 |

**공통 정보(콘텐츠 모델)**: 이름, 유형, 한 줄 소개, 날짜, 상태(운영 중 / 베타 / 개발 중 / 보관), 태그, 대표 이미지, 본문(Markdown),
유형별 필드, 공개 범위(공개 → Phase 3 에서 회원·의뢰인 추가), 추천 여부, 초안 여부.

- 콘텐츠 원본은 `content/assets/<slug>.md` 파일 하나다. 작품 하나를 추가하는 일은 파일 하나를 추가하는 일이다.
- 무거운 파일(exe·zip·고해상도 사진)은 git 밖의 `/opt/johnnystudio/files/` 에 두고 nginx 가 내준다.

### 3-2. Life Log (타임라인) ※ Phase 4 → 1 로 앞당김

원안에서는 외부 피드 수집과 함께 Phase 4 에 있었다. 하지만 **에셋 날짜와 직접 쓴 마일스톤만으로도** 타임라인은 바로 만들 수 있다.
1-1 원칙의 핵심이라 Phase 1 에 정적 타임라인으로 넣고, 외부 피드(GitHub·YouTube·RSS) 자동 수집만 Phase 4 에 남긴다.

### 3-3. Personalized Dashboard ('My Studio' 뷰) ※ 2단계로 나눔

- **Phase 1 (로그인 없음)**: 카드의 ⭐ 를 누르면 브라우저에 저장되고, `/studio/` 에서 모아 본다. 1-3 원칙의 "무마찰"을 바로 실현한다.
- **Phase 2 (로그인)**: 로그인하면 즐겨찾기가 서버에 동기화된다 (기기 간 공유).
  최근 본 항목, 즐겨찾기한 툴의 새 버전 알림을 더한다.

### 3-4. Client Project Room (의뢰인 전용 워크스페이스)

원안의 "GitHub-like Communication"을 프리랜서 업무 흐름에 대응시켰다.

| GitHub | Client Room | 설명 |
|---|---|---|
| Repository | **프로젝트 룸** | 의뢰 한 건 = 룸 하나. 초대받은 사람만 들어온다 |
| Issue | **요청·피드백** | 상태: 접수 → 진행 중 → 검수 대기 → 완료 (원안의 대기중/작업중/완료에 "검수 대기"를 추가) |
| Pull Request 리뷰 | **검수 요청** | 결과물 버전(v1, v2 …)을 올리면 의뢰인이 "승인 / 수정 요청"을 고른다 |
| Release | **납품** | 승인된 버전을 최종 납품으로 고정한다. 이후 받는 파일은 바뀌지 않는다 |
| Comment thread | **스레드 댓글** | 모든 결정이 이력으로 남는다 |

보완할 점은 다음과 같다.

- 결과물 다운로드 링크는 **만료형**(presigned URL)으로 하고, 접근 기록(감사 로그)을 남긴다.
- 알림은 **이메일부터** 시작한다. 실시간(WebSocket)은 실제로 필요해질 때 붙인다.
- 의뢰인 로그인은 **이메일 매직 링크**로 한다 (비밀번호 없음, 가입 마찰 최소화).
- 운영 측면: 견적·계약·NDA 는 Client Room 밖에서 처리하되 문서를 룸에 첨부할 수 있게 한다. 납품 후 보관 기간을 정한다.

### 3-5. Work with me (의뢰 창구) ※ 추가 제안

원안에는 **기존 의뢰인의 공간(Client Room)은 있지만, 새 의뢰인이 들어오는 길이 없다.** 협업 원칙(1-4)과 연결된 공개 페이지가 필요하다.

- 제공 서비스, 진행 방식(§3-4 흐름을 공개용으로 설명), 대표 사례(Library 와 연결), 연락 수단
- Phase 1 은 이메일 링크로 받고, 문의 폼은 백엔드가 생기는 Phase 2 에 붙인다

### 3-6. Interactive AI Hideout: JohnnyBot

- **Arkurator 의 RAG 백엔드(LangGraph · ChromaDB · 다중 LLM)를 재사용**한다. 이미 운영 중인 것을 다시 만들 필요가 없다.
- 지식원은 `content/` 파일이다. 이미 구조화되어 있어서 인덱싱이 쉽다.
- **공개 콘텐츠만 학습**한다. 의뢰인 비공개 자료는 절대 섞지 않는다 (인덱스와 권한을 분리한다).
- 답변에는 항상 출처(에셋 링크)를 붙인다.

### 3-7. 디자인 방향 (Minimalist Dark)

- 다크 테마 기본, 미니멀 아이콘, 넉넉한 여백. 강조색은 하나만 쓰고, 유형마다 작은 색 포인트를 둔다 (유형 배지).
- 한글 가독성을 우선한다 (Pretendard 자체 호스팅). 모션은 절제하고, `prefers-reduced-motion` 을 존중한다.

## 4. 검토 의견

### 4-1. 강점

- 작품·도구·협업을 하나의 정체성 아래 묶는 **"허브"라는 방향이 분명하다.**
- 셀프 호스팅 철학이 **실제 인프라와 경험**(M8 홈 서버, Arkurator 운영)과 맞물려 실현 가능성이 높다.
- Arkurator 에서 검증한 기술(FastAPI, PostgreSQL, RAG, 인증)을 **재사용**할 수 있다.
- 단계가 공개 → 개인화 → 협업 → 지능화 순서라서, 위험이 낮은 것부터 쌓인다.

### 4-2. 리스크와 보완

| # | 리스크 | 영향 | 보완 |
|---|---|---|---|
| R1 | 범위가 크다 (1인 개발, 원안 기준 기술 요소 10개 이상) | 완성 전에 지친다 | 단계마다 "출시 가능한 결과"를 정한다. 기술은 필요한 단계에서만 들인다 (§5) |
| R2 | 인증이 두 곳에 나뉜다 (NextAuth + FastAPI) | 권한 버그, 이중 유지보수 | **FastAPI 를 단일 인증 권위로** 둔다 (Arkurator `/auth/*` 와 같은 방식). Next.js 는 세션 쿠키만 전달한다 |
| R3 | `.exe` 배포의 신뢰 문제 | SmartScreen 경고, 변조 우려 | SHA-256 공개, 버전·변경 내역 공개. 가능하면 코드 서명, 바이러스 검사 결과 링크 |
| R4 | 웹 패키지(zip)를 같은 출처에서 실행 | XSS 로 포털 세션 탈취 | **별도 도메인**(예: `play.<도메인>`)에서만 서빙 + `iframe sandbox` + 엄격한 CSP. 로그인을 도입하기 전에 반드시 갖춘다 |
| R5 | 의뢰인 비공개 자료를 집 서버에 보관 | 유출 시 신뢰·법적 문제 | 초대 기반 접근, 만료 링크, 접근 로그, 암호화 백업(외부 1부 포함), 보관 기한 |
| R6 | 홈랩 가용성 (정전·회선 장애) | 납품 도중 장애 | 백업·복구 절차를 문서로 만든다. 중요한 납품에는 대체 전달 수단을 안내한다 |
| R7 | 대용량 파일 트래픽 | 가정 회선 업로드 대역폭, 프록시 약관 | 큰 공개 파일은 GitHub Releases 같은 외부 배포 채널을 함께 검토한다. Cloudflare 경유 대용량 파일 정책을 확인한다 `[확인 필요]` |
| R8 | 개인정보 (로그인 도입 시) | 개인정보보호법상 의무 | Phase 2 전에 개인정보처리방침을 쓴다. 최소한만 수집(이메일·이름)하고, 탈퇴·삭제 기능을 둔다 |
| R9 | 외부 임베드 (YouTube) | 추적 쿠키, 느린 첫 화면 | `youtube-nocookie.com` 을 쓰고, 클릭하기 전에는 썸네일만 보여 준다 |
| R10 | 콘텐츠 갱신 부담 | 허브가 금방 낡는다 | 작품 추가 = 파일 하나 추가. Phase 4 에서 외부 활동을 자동으로 수집한다 |

### 4-3. 원안에서 달라진 점

1. 방문 목적별 **네 구역** 구조를 추가했다 (§0).
2. 원칙마다 실천 기준을 붙이고, **신뢰(Trust by Design)** 원칙을 추가했다 (§1).
3. 에셋 **유형표와 공통 콘텐츠 모델**을 정의했다 (§3-1).
4. **Life Log** 를 Phase 1 로 앞당겼다 (정적 타임라인). **My Studio** 는 로그인 없는 단계부터 시작한다.
5. Client Room 에 **GitHub 개념 대응표**와 "검수 대기" 상태, 만료 링크, 매직 링크 로그인을 추가했다.
6. 새 의뢰인을 위한 **Work with me** 를 추가했다.
7. 인증을 **FastAPI 단일 권위**로 바꾸자고 제안했다 (NextAuth 대신).
8. MinIO·Redis·WebSocket 의 **도입 시점을 늦췄다** (§5). JohnnyBot 은 **Arkurator 재사용**으로 바꿨다.
9. 리스크 10건, 성공 지표, 하지 않을 것, 열린 질문을 추가했다.

## 5. 기술 스택과 도입 시점

"한꺼번에 다 깔기" 대신 **단계가 필요로 할 때 들인다.** 운영할 구성 요소가 적을수록 1인 개발이 오래 간다.

| 구분 | 기술 | 역할 | 도입 | 원안 대비 |
|---|---|---|---|---|
| Frontend | **Next.js (App Router) + TypeScript + Tailwind CSS** | 공개 페이지는 정적 생성(SEO), 대시보드는 클라이언트 렌더링 | Phase 1 | 같음 (TypeScript 명시) |
| 콘텐츠 | Markdown + YAML 머리말 (`content/`), zod 검증 | 에셋·Life Log·프로필 원본 | Phase 1 | 추가 |
| 공개 파일 | nginx `/files/` | exe·zip·사진 | Phase 1 | MinIO 대신 |
| 공개 | **Cloudflare Tunnel** | 외부 도메인 연결, HTTPS (포트포워딩·인증서 발급 불필요) | 공개할 때 | 같음 |
| Backend | FastAPI | 인증, 즐겨찾기, 의뢰 룸 API | Phase 2 | 같음 |
| DB | PostgreSQL | 회원, 즐겨찾기, 룸·이슈·댓글 | Phase 2 | 같음 |
| 인증 | FastAPI 단일 인증 (Google OAuth + 이메일 매직 링크, httpOnly 세션 쿠키) | 개인화, 의뢰인 구분 | Phase 2 | NextAuth 대신 |
| 배포 | Docker Compose | 백엔드·DB 실행 | Phase 2 | 시점 명시 |
| Storage | MinIO (S3 API) | 의뢰인 비공개 결과물, 만료형 링크 | Phase 3 | Phase 1 → 3 |
| 알림 | 이메일 → (필요하면) WebSocket | 검수 요청·댓글 알림 | Phase 3 | 실시간은 뒤로 |
| Cache | Redis | 세션·요청 제한·피드 캐시 | 필요할 때 | 필수 → 선택 |
| AI | Arkurator RAG 백엔드 재사용 (LangGraph · ChromaDB) | JohnnyBot | Phase 4 | 재사용 |

**Phase 1 은 Next.js 정적 내보내기**(`output: "export"`)로 만든다. 서버 프로세스 없이 nginx 가 파일만 내주므로,
지금의 배포 방식(릴리스 폴더 + `current` 링크)을 그대로 쓴다. Phase 2 에서 Next.js 서버 모드와 FastAPI 로 넘어간다.

## 6. 단계별 구현 계획

### Phase 1: 공개 허브 (Showcase) — 첫 출시 단위

- 다크 테마 디자인 시스템, 공통 레이아웃
- 홈, Library(검색·유형 필터), 에셋 상세, Life Log, About, Work with me, My Studio(브라우저 저장 즐겨찾기), 404
- 유형별 뷰어: 실행 링크, 다운로드 패널(SHA-256·검증 방법), YouTube 라이트 임베드, 사진 갤러리, 원문 링크
- 콘텐츠 파일 체계와 검증, nginx `/files/`
- 도메인 연결 + Cloudflare Tunnel 로 공개
- **완료 기준**: 대표 작품 5~10개 등록, 모바일·접근성 점검, 공개 주소로 접속 가능

### Phase 1.5: 웹 패키지 샌드박스 (선택)

- 별도 출처(예: `play.<도메인>`)에서 zip 패키지를 풀어 서빙하고, 상세 화면에 격리된 iframe 으로 넣는다

### Phase 2: 회원과 My Studio

- FastAPI + PostgreSQL + Docker Compose, Next.js 서버 모드 전환, nonce 기반 CSP
- 로그인 (Google OAuth, 이메일 매직 링크), 즐겨찾기 동기화 (브라우저 저장분을 가져옴)
- 개인정보처리방침, 회원 탈퇴·삭제, 문의 폼

### Phase 3: Client Room

- 초대·권한 분리, MinIO 비공개 저장소, 만료형 다운로드 링크
- 결과물 버전 → 검수 요청 → 승인 → 납품 흐름, 요청·피드백 스레드(상태값 포함)
- 이메일 알림, 감사 로그, 암호화 백업

### Phase 4: 자동 Life Log + JohnnyBot

- 외부 피드(GitHub, 블로그 RSS, YouTube) 주기 수집 → Life Log 에 합친다
- Arkurator RAG 재사용으로 JohnnyBot 탑재: 방문자에게 툴 추천, 의뢰인 FAQ 응대 (공개 콘텐츠만)
- 쿠키 없는 셀프 호스팅 분석으로 관심사 파악

## 7. 성공 지표 (제안)

| 단계 | 지표 |
|---|---|
| Phase 1 | 홈에서 상세까지 2클릭 이내, 실행·다운로드 클릭 수, 의뢰 문의 수 |
| Phase 2 | 재방문율, 즐겨찾기를 쓰는 사람 수 |
| Phase 3 | 의뢰 소통 중 메일 대신 룸에서 처리된 비율, 요청부터 납품까지 걸린 기간 |
| Phase 4 | JohnnyBot 답변을 통해 이어진 클릭 수 |

측정은 쿠키 없는 셀프 호스팅 방식으로 한다 (nginx 로그 집계, 또는 Umami 같은 도구).

## 8. 하지 않을 것 (Non-goals)

- 공개 자료에 회원가입을 강요하지 않는다
- 범용 SNS·커뮤니티 기능(공개 댓글, 좋아요 피드)은 만들지 않는다
- 의뢰인이 아닌 사람의 파일 업로드는 받지 않는다
- 결제는 만들지 않는다. 필요하면 외부 서비스로 처리하고, Phase 3 이후에 다시 검토한다
- 검증된 오픈소스로 충분한 것은 직접 만들지 않는다
