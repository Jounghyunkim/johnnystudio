# 기능: Showroom (회원이 만든 웹 서비스 소개)

> **상태**: 구현 완료 (개발 서버에서 동작, 운영 서버 설정 전). 결정: [ADR-0012](../../04_architecture/adr/0012-member-store.md) 결정 12·13 (제안됨)
> **Last Updated**: 2026-11-26
> **짝**: [Store](store.md) (내려받는 Windows 앱). 원칙·올리는 회원·약관·검토 화면을 함께 쓴다

## 왜 (문제와 목적)

- 사용자 요청 (2026-11-24): "앱을 공유하는 Store와 동일한 레벨로 사용자들이 만든 서비스를 공유하고 설명하는 페이지를 적절한 이름을 붙여서 추가해 줘."
- 이름 **Showroom**: 앱을 받아 가는 Store 와 짝인 '보여 주고 설명하는 곳'. "Services" 는 Work with me 의 서비스와 헷갈려 쓰지 않았다
- PHILOSOPHY 의 **바로 써 보게**: 로그인 없이 목록·설명을 보고 바로 서비스를 연다

## 무엇을 (범위)

- **포함**
  - 회원이 웹 서비스의 이름·https 주소·한 줄 소개·설명·분류·아이콘·화면 그림을 등록 → 운영자 승인 뒤 공개
  - 목록(검색·분류 9개·정렬), 상세(서비스 열기, 화면 그림, 설명, 공유 주소, 신고), 내 서비스(고치기·그림·지우기), 운영자 검토(Store 검토 화면 안)
  - 운영자는 남의 서비스도 고치고(이름·주소·글·아이콘·소개 자료) 지운다 (2026-11-26, Store 와 같다)
  - Library 의 공개된 웹 서비스를 '공식'으로 함께 보여 준다. 2026-11-26 부터 Arkurator 는 DB 의 서비스(운영자 계정이 소개한 것, `official`)로 관리한다 ([ADR-0014](../../04_architecture/adr/0014-official-apps-in-store-db.md), 작품 파일에 `showroomService`). 코드가 없는 웹 서비스만 작품 파일에서 합친다
  - 공식 서비스 지우기: Store 와 같다 (작품 자체를 지운다, 개발 서버·운영자, [store.md](store.md) 의 '공식 항목 지우기'). Arkurator 는 Life Log·서비스 소개가 가리키고 있어 그 연결을 빼기 전에는 지워지지 않는다
- **포함하지 않음**
  - 사이트 안에서 남의 서비스를 띄우기(iframe). 바깥 링크로만 연다
  - 방문·클릭 수 세기 (추적하지 않는다)
  - 도메인 소유 확인 (재검토 조건)

- **소개 자료** (2026-11-25, [ADR-0013](../../04_architecture/adr/0013-listing-kit.md), [기능 명세](listing.md)): Store 와 같은 항목. 화면 그림은 한 장 → 그림 모음 10장 (예전 한 장은 그림 모음이 없을 때만 보인다).
  웹 화면 캡처는 AI 도구가 회원 PC 에서 Playwright 로 한다 (서버는 회원 주소를 열지 않는다). 소개 꾸미기 `/showroom/listing/?id=`

## 화면과 동작

| 주소 | 화면 | 누가 |
|---|---|---|
| `/showroom/` | 머리글(설명 아래, 가로줄 위)에 **'서비스 등록'**·**'검토'**(운영자만) 버튼. 목록: 공식(빌드된 HTML) + 회원(API). 카드: 아이콘·이름·'공식'·소개한 사람·분류·소개·호스트·**열기**(새 탭) | 누구나 |
| `/showroom/service/?id=<코드>` | 상세: 머리글에 소개한 사람·운영자에게만 **'편집'**(소개 꾸미기 화면으로), 옆 칸 아래에 **'서비스 지우기'**(소개한 사람·운영자) (겹치던 '검토 화면'은 2026-11-26 에 뺐다), 서비스 열기(주소 표시), 화면 그림, 설명, "회원이 소개한 서비스" 안내(주소 확인), 공유 주소, 신고 | 누구나 (검토 중은 소개한 사람·운영자만) |
| `/showroom/new/` | 서비스 등록: 로그인 → (처음이면) 표시 이름·약관 동의 → 양식(그림은 선택) → 검토 요청 | 회원 |
| `/showroom/mine/` | 내 서비스: 상태·사유, 열기, 고치기(`<dialog>`), 아이콘·화면 그림 넣기/바꾸기, 지우기 | 회원 |
| `/store/manage/` | 검토 화면 아래 "Showroom" 절: 검토 대기(주소 열어 보기·승인·반려), 신고(숨기기·조치함·기각), 최근 공개(숨기기), 숨긴 서비스(검토 대기로 되돌리기). 검토 대기·최근 공개·숨긴 서비스마다 **편집**(소개 꾸미기 화면)·**지우기** | 운영자 |

메뉴: Library · Life Log · Work with me · About **|** Store · Showroom (1024px 보다 좁으면 메뉴 버튼 안). 홈 히어로에도 Store·Showroom 버튼.

### 상태

```
검토 대기 ──승인──▶ 공개 ──주소 바꿈──▶ 검토 대기 (승인까지 목록에서 빠진다)
    └──반려──▶ 반려 ──고쳐서 저장──▶ 검토 대기
공개 ──운영자──▶ 숨김 ──되돌리기──▶ 검토 대기
```

- 이름·소개·설명·분류·그림 수정은 바로 반영 (신고·숨김으로 사후 대응)
- 운영자가 남의 서비스를 고치면 **상태를 바꾸지 않는다**: 주소를 바꿔도 다시 검토 대기로 돌리지 않고(운영자가 본 주소), 반려된 서비스를 대신 다시 내지 않는다. 고친 일·지운 일은 서버 로그에 남는다 (약관 제5조 5, 판 `2026-11-26`)
- 회원 차단은 Store 와 같다: 차단하면 Showroom 서비스도 목록에서 빠지고 새로 소개할 수 없다

## 구조

- API `api/app/showroom/`: `models.py`(`showroom_services`·`showroom_reports`), `service.py`(주소 검사 `clean_url`, 응답 모양, 탈퇴 정리), `router.py`(`/api/showroom/`)
  - 올리는 회원·운영자·글 정리·신고 형식은 Store 것을 함께 쓴다 (`app/store/router.py` 의 도우미, `store_publishers`)
  - 그림: `app/store/analyze.py` 의 `run_icon_isolated`·`run_screenshot_isolated` (자식 프로세스) → `<store_dir>/showroom/{icons,shots}`
  - 한도: 24시간에 새 소개 10개, 회원당 50개, 아이콘 1MB, 화면 그림 5MB
- 웹: `src/lib/showroom.ts`, `src/components/showroom/`, `src/app/showroom/{,service,new,mine}/page.tsx`, 공식 목록 `content.ts` 의 `getOfficialShowroomServices()`
- nginx: `/api/showroom/uploads` 만 본문 6m (그 밖의 `/api/` 는 16k)
