# 기능: 설정 화면 (`/settings/`)

> **상태**: 완료 (2026-11-26, 사용자 요청)
> **Last Updated**: 2026-11-28

## 왜 (문제와 목적)

내 계정 상태, 화면 테마·로그인 이메일 같은 편의 설정, 캐시·브라우저 저장 값 지우기가 여러 곳(바닥글·계정 화면·로그인 화면)에 흩어져 있었다.
운영자는 회원·Store·Showroom 현황을 한눈에 볼 곳이 없었다 (검토 화면은 할 일 목록이다).
**설정** 버튼 하나로 모은다 (처음에는 바닥글 오른쪽 아래, 2026-11-28 부터 헤더 오른쪽 위).

## 무엇을 (범위)

- **포함**
  - 들어가는 곳: 헤더 오른쪽 위의 **설정**(⚙) 아이콘 버튼, 맨 오른쪽 (모든 페이지, 휴대폰은 메뉴 버튼 ☰ 왼쪽). 2026-11-28 사용자 요청으로 바닥글 오른쪽 아래에서 옮겼다
  - **사용자 현황**
    - 비회원: 로그인 안내, 이 브라우저의 즐겨찾기 개수 (로그인하면 계정으로 옮긴다고 알린다, ADR-0017)
    - 회원: 내 계정 (이메일·**표시 이름**·가입한 날·마지막 로그인·로그인 방법·권한·계정에 저장된 즐겨찾기 개수), 계정 관리·My Studio·내 앱·내 서비스 바로 가기
      - 이름표는 '표시 이름' 하나로 부른다 (2026-11-28 사용자 요청, 예전 'Store·Showroom 표시 이름'). 회원 한 사람에 하나이고 Store·Showroom 의 '올린 사람'·'소개한 사람'으로 공개된다.
        계정 화면(`/account/`)의 '계정 정보'와 같은 값·같은 부품이다 (`components/display-name.tsx`). 헤더의 계정 버튼에도 보인다
      - **표시 이름 바꾸기** (2026-11-26): '바꾸기' → 칸에서 고쳐 저장. 이름만 바꾸고(`PATCH /api/store/me/publisher`) 약관에 다시 동의하지 않는다. 앱·서비스 화면의 '올린 사람'·'소개한 사람'에 바로 보인다.
        아직 정하지 않았으면 '정하기' → 이용약관 동의·만 14세 확인과 함께 정한다(`POST`, 앱 올리기 화면과 같다). 이용 제한 중에는 버튼이 없다
    - 운영자: **전체 현황** (개수만): 회원(전체·최근 7일/30일 가입·최근 24시간에 들른 회원·로그인 유지·최근 7일 로그인·비밀번호를 정한 회원),
      Store(올리는 회원·이용 제한·검토 대기 버전·처리할 신고·앱 상태별), Showroom(처리할 신고·서비스 상태별). 새로 읽기, 검토 화면 바로 가기
      - **차트** (2026-11-26 사용자 요청 "시각적인 요소로 분석", `components/settings/admin-charts.tsx`, 계산은 `lib/chart.ts`):
        가입 추이(하루 한 막대, 최근 30·90일 고르기, 마우스·키보드 툴팁에 그날 가입·누적, '표로 보기'), 마지막 로그인 분포(오늘·1~6일·7~29일·30일 이상),
        앱·서비스 상태(얇은 나눔 막대 + 이름·개수·비율 범례), 내려받기가 많은 앱(공개된 앱 8개까지). 날짜는 한국 시간. 값은 `/api/site/admin/stats` 의 `trends`(개수만)
      - 색: 한 줄 값은 강조색, 상태는 `--color-chart-*` (dataviz 검사기로 고름: 어두운 테마 모두 통과, 밝은 테마는 색각 구분 ΔE 8.0 경고 → 범례에 이름·개수를 늘 함께). 위치·크기는 SVG 속성만 쓴다 (CSP 가 style 속성을 막는다)
  - **앱 설정**: 화면 테마, 로그인 이메일 기억(보기·잊기). 운영자에게는 **운영 설정**(읽기 전용): 실행 환경·사이트 주소·회원 DB 종류·로그인 메일 방식·로그인 유지 일수·운영자 수·새 앱 받기·바이러스 검사·올리기 한도·약관 판
  - **일반 설정**
    - **캐시 지우기**: `POST /api/site/clear-cache` 의 응답 머리글 `Clear-Site-Data: "cache"` 로 브라우저가 이 사이트의 HTTP 캐시를 지우고, 화면을 새로 고친다. 쿠키는 지우지 않으므로 로그인은 그대로다.
      브라우저는 HTTPS(또는 localhost)에서만 따른다. 아니면 화면에 강력 새로 고침(Ctrl+Shift+R)을 안내한다
    - **이 브라우저에 저장된 값**: localStorage 의 `johnnystudio:` 키만 보여 주고 골라 지운다 (로그인 전에 넣은 즐겨찾기·기억한 이메일·테마·그 밖의 값. 계정의 즐겨찾기는 여기에 없다). `<dialog>` 로 확인한다. 다른 사이트의 키는 건드리지 않는다
- **포함하지 않음**
  - 회원 목록·이메일 보기. 현황은 개수만 낸다 (개인정보처리방침: 이메일은 운영자가 검토·신고 처리에만 쓴다)
  - 운영 설정 바꾸기. 원본은 환경 변수(`api.env`, 개발은 `api/.env.local`)다 (`app/config.py`). 화면에서 바꾸게 하려면 DB 에 설정 테이블을 두는 결정(ADR)이 먼저다
  - 서버 쪽 캐시 지우기 (API 응답은 `no-store` 라서 서버가 따로 들고 있는 화면 캐시가 없다)

## 구조

- API `api/app/site.py` (`/api/site/`): `POST /clear-cache`(누구나, Origin 검사), `GET /admin/stats`(운영자, `store/router.py` 의 `_admin`)
- 웹: `src/app/settings/page.tsx`(칸 제목·차례는 빌드된 HTML), `src/components/settings/settings-panels.tsx`(내용은 브라우저에서), `src/lib/site.ts`(API·저장 값 목록·지우기)
  - 저장 값을 지우면 `storage` 이벤트를 내서 즐겨찾기·테마·기억한 이메일 화면이 바로 새 값을 읽는다 (테마를 지우면 바로 어두운 테마)
- 색인 안 함 (`robots: noindex`)
